- **Verbatim:** rule 1: "Si la casilla no contiene valor y corresponde a un valor numérico colocar cero (0) (Si es una factura, nota de crédito anulada, colocar cero (0)). a) Libro de compras, Columnas (G, H, I, J y K) b) Libro de ventas, Columnas (G, H, I y J)" / rule 2: "Las NOTAS DE CRÉDITO, se identificarán (NC), el valor de las notas de crédito NC se registran con valor negativo, y las NOTAS DE DÉBITO, se identificarán (ND), el valor de las notas de débito ND se registran con valor positivo. Para las notas de crédito: a) Se coloca “NC” en la Columna B del libro de compras y de ventas. b) Los valores de las Columnas (G, H, I, J y K) del libro de compras deben ser negativos. c) Los valores de las Columnas (G, H, I y J) del libro de ventas deben ser negativos. Para las notas de débito: d) Se coloca “ND” en la Columna B del libro de compras y de ventas. e) Los valores de las Columnas (G, H, I, J y K) del libro de compras deben ser positivos. f) Los valores de las Columnas (G, H, I y J) del libro de ventas deben ser positivos." / rule 3: "Ninguna columna de los libros debe ir en blanco, excepto la columna serie, si el documento no tiene serie, la casilla serie debe quedar en blanco. a) Libro de compras, Columnas C b) Libro de ventas, Columnas C" / rule 4: "En el NIT, evitar utilizar guion (-), ni (_). Utilizar (-), (_) si y solo si es parte de un NIT, Ejemplo 45856-7 o 45856_7, si no es parte del NIT podría lanzar error en la carga del archivo. En el caso de importaciones colocar el NIT del contribuyente que solicita la devolución de crédito fiscal. Y en el caso del libro de ventas el NIT e ID (NIT internacional), deberán incluirse en las operaciones mayores a Q2,500.00 de forma obligatoria a partir de enero 2023. c) Libro de compras, Columnas E (Nota: En columna F consignar el nombre o razón social del proveedor) d) Libro de ventas, Columnas E (Nota: En columna F consignar el nombre o razón social del cliente)" / rule 5: "En ninguna de las columnas utilizar comas (,). a) Libro de compras, Columnas (A, B, C, D, E, F, G, H, I, J, K, L, M, N, O y P) b) Libro de ventas, Columnas (A, B, C, D, E, F, G, H, I, J y K)" / rule 6: "Todas las columnas consignar en formato TEXTO, excepto la columna de la fecha / a) Libro de compras, Columnas (B, C, D, E, F, G, H, I, J, K, L, M, N, O y P) consignar formato TEXTO / b) Libro de compras, Columna (A) consignar formato FECHA CORTA. El formato debe ser “dd/MM/yyyy”, ejemplo 01/01/2016. / c) Libro de ventas, Columnas (B, C, E, F, G, H, I, J, y K) consignar formato TEXTO / d) Libro de ventas, Columna (A) consignar formato FECHA CORTA. El formato debe ser “dd/MM/yyyy”, ejemplo 01/01/2016."
- **Gloss:** Full cell-format contract for both CSVs: (i) numeric buckets **zero-filled** (0) when empty — voided invoices/credit notes also 0; (ii) **NC rows negative, ND rows positive** across all value columns (compras G-K, ventas G-J) with NC/ND in column B; (iii) **no blank cells anywhere except SERIE (C)** when the document has no series; (iv) NIT column: no `-`/`_` **unless genuinely part of the NIT** (e.g. 45856-7); **imports rows carry the requesting taxpayer's own NIT**; ventas NIT + **ID (NIT internacional)** mandatory for operations **> Q2,500.00 since January 2023** (a dated obligation row); (v) **no commas in ANY column** (all columns enumerated — therefore no thousands separators; decimal separator implied "." by the Q2,500.00/0.00 examples, never stated); (vi) **all cells TEXT format except date column A = FECHA CORTA `dd/MM/yyyy`** (e.g. 01/01/2016) — i.e. even amounts are text cells. (Rule 6's list for ventas omits D by typo — "B, C, E, F…" — column D (NUMERO) is obviously intended under TEXTO with all non-A columns; flagged, not corrected.)
- **Candidate CRs:** export-format CRs: amounts as text with `.` decimal, no thousands separators, zero-fill empties; date column `dd/MM/yyyy`; negative NC / positive ND value rows; only SERIE may be blank; NIT without dash/underscore unless intrinsic; ventas rows > Q2,500 must carry cliente NIT/ID (incl. NIT internacional) — effective 2023-01
- **Topics:** fiscal-reporting; catalogs (CSV export format); IVA; devolución crédito fiscal
- **Doubts/xref:** OQ-5 (Q2,500 statutory source), OQ-6 (encoding/decimal separator not explicit)

## Open questions (file-level, numbered OQ-1..)

- **OQ-1:** **Neither document prints a date/version in its text layer.** The task brief asserts `63_` prints 05-12-2023; the extraction contains no such string (only the business rule "a partir de enero 2023", rule 4) — the 05-12-2023 may sit in an image/footer the text layer dropped. `62_` likewise undated (only "Página N de 8"). Both are undated procedural docs; internal terminus: `63_` post-2023-01.
- **OQ-2:** `63_`'s two template tables are images; their text layer extracts interleaved (both books' group headers mixed). The column-letter mapping (clean text) is authoritative; the **group-header spans** (esp. compras "VALOR BASE" vs "VALOR CRÉDITO FISCAL" over G-K) cannot be unambiguously reconstructed — notably compras has no explicit crédito-fiscal column while ventas does (I, DEBITO FISCAL). Verify spans against the original PDF tables before freezing any layout diagram.
- **OQ-3:** `62_` cites **no legal basis** (no art. 24 D27-92 / art. 29 LAT / CT reference, unlike `56_` which cites art. 72 D10-2012). The 4-year window, the trimestral/semestral granularity and the entitlement test must be sourced from W-GT2 (`23_`/`24_`) and `25_` — this file only evidences the mechanics.
- **OQ-4:** `62_` p.2 estado list "…ADMITIDO, NO ADMITIDO, ASIGNADO Y RESUELTO" — ambiguous whether "ASIGNADO Y RESUELTO" is one combined state or the last two of seven/eight states. Quote left as printed.
- **OQ-5:** `63_` rule 4's "el NIT e ID (NIT internacional), deberán incluirse en las operaciones mayores a Q2,500.00 de forma obligatoria a partir de enero 2023" imports an external statutory rule (FEL/LAT invoicing-identification regime) with a dated start (2023-01) — its instrument is outside this corpus. Also unclear how "ID (NIT internacional)" is to be rendered in the single NIT column (E) when a foreign client has no Guatemalan NIT.
- **OQ-6:** Container details NOT specified anywhere: file encoding (ANSI vs UTF-8), BOM, line endings, quoting/escaping (moot given the comma ban), maximum rows/file size, decimal separator (only implied "." by "Q2,500.00"/"0.00" examples) and negative-number rendering (leading `-` implied, not stated). Any export implementation must fix these and test against the real loader.
- **OQ-7:** Doc-type catalog oddities as printed: row 3 names "FACTURA ELECTRÓNICA FACE" but codes it **FCE** (the FACE/FCE pairing is as printed); "FACTURA ELECTRÓNICA FEL" (row 4) has no separate code column value other than FEL; "FACTURA CAMBIARIA FCAM" (row 12) lacks the "ELECTRÓNICA" qualifier of row 13 (FELCAM). Kept verbatim; verify codes against SAT's current catalog before reuse (xref `29_30_` FEL catalogs evidence for FEL-side document types).
